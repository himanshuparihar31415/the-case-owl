# The engine ⇄ platform contract

Three parties speak it: Node (`server/modules/engine/`), the engine (`engine/app/`), and the page
(`src/hooks/useEngineInterview.ts`). A change on one side that the other two do not know about breaks
live interviews, so every change touches all three in one go.

- Source of truth for shapes: `engine/app/contract.py` (pydantic, camelCase on the wire).
- Exported JSON Schemas: `engine/contract/*.json`, regenerated by `uv run python tools/export_schemas.py`.
  `tests/test_contract.py` fails when they are stale. Never edit them by hand (a hook blocks it).
- Prose and rules: `docs/engine-contract.md`. Paths carry the version (`/v1`); section 8 has the rules.

## Changing it

1. Within v1, changes are additive only: a new optional field or a new message. Each side ignores what
   it does not know, so additive changes can deploy in any order. A rename, removal or meaning change is
   breaking: it means `/v2`, served alongside v1 during the switch. Plan that with the user first.
2. Change `contract.py`, export the schemas, update the doc (note the addition and its date where the
   doc lists additions, as with "added 24 Oct"), then the Node client and the page hook.
3. Tests: engine tests cover the engine side; exercise the Node side through the stub or a real call.

The `/contract-change` skill walks through this; the `contract-keeper` agent checks that all three
sides agree.
